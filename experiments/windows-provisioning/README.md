# Experiment: deploy-time configuration of Windows VMs

Checks which mechanisms actually run configuration on a Windows VM when it is deployed in Azure.
Findings: [docs/research/windows-provisioning.md](../../docs/research/windows-provisioning.md).

## Test matrix

| Test | Mechanism | Payload | Expected |
|------|-----------|---------|----------|
| A | `custom_data` | [scripts/customdata.ps1](scripts/customdata.ps1) (installs 7-Zip) | Lands in `C:\AzureData\CustomData.bin`, not executed |
| B | `user_data` | [scripts/userdata.ps1](scripts/userdata.ps1) (writes a marker) | Readable from IMDS, not executed |
| C | Custom Script Extension | [scripts/cse-wrapper.ps1](scripts/cse-wrapper.ps1) runs the custom data payload | 7-Zip installed |
| D | Managed Run Command | [scripts/runcommand.ps1](scripts/runcommand.ps1) (installs PowerShell 7) | PowerShell 7 installed |

Every payload writes a marker file to `C:\probe`. A payload that Azure executes on its own would
leave an `*-autorun.marker`. [scripts/verify.ps1](scripts/verify.ps1) collects the results.

The VM has no inbound access (NSG with default rules only). A Standard public IP gives it explicit
outbound internet access for the downloads.

## Run

From PowerShell, with the service principal variables (`ARM_*`) and the proxy set up as described
in [docs/runbooks/vdi-setup.md](../../docs/runbooks/vdi-setup.md). Create
`<environment>.azurerm.tfbackend` in this directory from
[example.azurerm.tfbackend](example.azurerm.tfbackend).

The experiments use Windows 11 Pro 26H2 ([win11.tfvars](win11.tfvars)):

```powershell
terraform init -reconfigure -backend-config="<environment>.azurerm.tfbackend"
terraform apply -var-file win11.tfvars

az vm run-command invoke -g rg-awa-poc-cfgtest-w11 -n vm-cfgtest `
  --command-id RunPowerShellScript --scripts "@scripts/verify.ps1" `
  --query "value[].message" -o tsv

terraform destroy -var-file win11.tfvars
```

The backend file holds one state key, so run one variant at a time and destroy it before
switching. Without `-var-file win11.tfvars` the configuration deploys Windows Server 2022, the
variant of the first experiment run.

The admin password is generated by `random_password` and only kept in the Terraform state, which
lives in the backend storage account.
